## Issues
CRITICAL (blocks pass): none.

Informational (does not block):
1. [Medium] `backend/src/test/java/vn/tsolve/review/ReviewStorageIT.java:204-245`: the only AC-004.13 test seeds one ticket and one decision. With one row, `select ticket_id from ticket_import_decision where reviewer = 'legacy-pm'` equals the ticket's UUID even if the remap joined decisions to the wrong ticket. So "each decision still linked to its original Ticket" is not really tested. Of "Solution data" it checks only `resolution_steps`, used as a filter. It does not check `title`, `symptoms`, `root_cause`, `scope`, `workaround`, `status`, `source`, `import_batch_id`, or the decision's `decision` / `decided_at`. The SQL is correct on reading (`008-review-ticket-storage.sql:10-13`), so this is a test gap, not a defect. Fix: seed two imported tickets, linked to an `import_batch`, with two decisions each (different reviewers). After the upgrade, assert for each decision `(reviewer, decision, decided_at)` → the UUID of its own `source_ticket_id`. Also assert the full Solution / status / source / `import_batch_id` of each ticket, and that the ticket and decision counts are unchanged.
2. [Low] `backend/src/test/java/vn/tsolve/ticket/service/impl/ImportConfirmIT.java:117-124, :321-326`: the AFTER_COMMIT listener records only `event.ticketIds().size()`. Only the mock-based unit test (`ImportConfirmServiceImplTest:301`, ids set by reflection) shows that the ids are the UUID keys of the new rows. Fix: let `PublishedEvents` keep the ids, and assert in `:321` that they equal `select ticket_id from ticket` (as a set).
3. [Info] `backend/src/main/resources/db/changelog/changes/008-review-ticket-storage.sql:7`: `ADD COLUMN ... NOT NULL DEFAULT gen_random_uuid()` uses a volatile default, so PostgreSQL rewrites the whole `ticket` table under an `ACCESS EXCLUSIVE` lock. This is acceptable at capstone data sizes. Note it if a tenant ever has a large `ticket` table. No change needed now.
4. [Info] `harnessclaude/artifacts/04-plans/import-ticket-list/design.md`: the 2026-11-06 spec change (STORY-004, AC-004.10 / AC-004.13) has no "Change" section and no Edge Cases & Risks rows. For example: a decision whose ticket is missing, upgrade order against Search's and Review's changesets, an existing preview during the upgrade. Task 30 in `tasks.md` exists, so this is an artifact gap only. Fix: add the rows when the plan is next touched.
